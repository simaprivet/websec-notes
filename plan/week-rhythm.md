# Ритм недели

Назад к [плану](../appsec-plan.md).

Два слоя. Так сделано затем, чтобы выход на работу не требовал переписывать план:
надстройка просто отваливается, ядро остаётся.

## Ядро — 60 минут, не пропускается

1. Одна лаба PortSwigger
2. Конспект по ней: **уязвимость → эксплуатация → фикс в коде**
3. Коммит

Один день — одна лаба. Это минимум, ниже которого день не считается.
Конспект пишется сразу после лабы, а не копится на выходные: через сутки механика
уже вспоминается неточно, и в конспект попадает результат вместо причины.

## Надстройка — вторые 60 минут, по дням

| День | Что |
|---|---|
| Пн | **Python.** Скрипт на `httpx`, воспроизводящий сегодняшнюю уязвимость |
| Вт | **`security-reviewer`** по своему уязвимому коду, сравнение с собственным разбором |
| Ср | **Bandit,** один-два уровня на разминку |
| Чт | **Теория.** Раздел PortSwigger целиком, а не только под лабу |
| Пт | **Инструмент** на Agent SDK или правило Semgrep |
| Сб | **ВКР.** Один вопрос из `IDEAS.md`, письменно, один коммит |
| Вс | Выходной. Без исключений |

Вторник и пятница — те дни, где живёт [повторение вайбкодинга](repetition.md).

## Почему воскресенье жёстко выходное

Август показал обратную зависимость: неделя без выходного заканчивается не большим
объёмом, а провалом на три дня. Пропущенное воскресенье дороже пропущенного вторника.

## Что делать, когда день сорвался

Сорванный день — это один день. Не «неделя насмарку» и не повод догонять двойным объёмом:
попытка догнать почти всегда заканчивается вторым провалом. Просто следующий день по плану.

Два сорванных дня подряд — сигнал, что бюджет выбран неверно, и его надо пересмотреть,
а не давить силой воли.
