# Апрель 2027 — code review на чужом коде

Назад к [фазе A](../phase-a.md) · [план](../../appsec-plan.md)

## Цель месяца

Перестать работать с заранее сломанными лабами. Реальный код не подсвечен, уязвимость в нём не гарантирована, и большая часть времени уходит на понимание чужой логики. Это и есть работа AppSec-инженера.

## Темы

- [Инструменты](../../tools/tools.md)

## По неделям

1. Выбор 2–3 небольших открытых проектов на Python или JS. Критерий: живые, но не гигантские
2. Разбор архитектуры до чтения кода: где границы доверия, куда входят данные
3. Собственно ревью. Semgrep как первый проход, руки как второй
4. Оформление находок: issue или PR с объяснением, почему это проблема

## Надстройка этого месяца

Ядро меняется: вместо лабы — час чужого кода. Конспект становится отчётом по ревью. Это единственный месяц, где ядро отходит от PortSwigger.

## Что должно появиться к концу

- Минимум один разбор, доведённый до issue или PR в чужом репозитории
- Отчёт по ревью в формате, который не стыдно показать
- Честная заметка о том, сколько времени ушло на понимание чужого кода против поиска проблем — цифра удивит
