# SQL injection

Тема фазы A · по плану — [сентябрь–октябрь 2026](../plan/months/2026-09.md) · назад к [плану](../appsec-plan.md)

## Что это

Приложение собирает SQL-запрос склейкой строк с пользовательским вводом, и ввод из-за этого
может изменить **структуру** запроса, а не только его данные. Базовый случай класса
«данные разбираются как управляющая конструкция» — того же, что стоит за command injection
и за парой уровней Bandit.

## Что уметь к концу темы

- Отличать, где ввод попадает в структуру запроса, а где остаётся значением
- Извлекать данные через UNION и через слепые методы
- Объяснить, почему параметризованный запрос закрывает проблему, а экранирование — нет

## Как чинится в коде

Параметризованный запрос: шаблон и значения уходят в базу **отдельно**, база разбирает
структуру до того, как получит значения — поэтому значение не может её изменить.

Экранирование — не замена: оно зависит от кодировки, контекста и дисциплины на каждом вызове.
Там, где параметризовать нельзя (имя таблицы, направление сортировки), — белый список значений.
