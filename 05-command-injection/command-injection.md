# Command injection

Тема фазы A · по плану — [октябрь 2026](../plan/months/2026-10.md) · назад к [плану](../appsec-plan.md)

## Что это

Приложение передаёт пользовательский ввод в командную оболочку, и ввод разбирается
оболочкой как часть команды. То же самое, что SQL-инъекция, но интерпретатор — shell,
а цена ошибки выше: выполнение кода на сервере.

## Что уметь к концу темы

- Находить места, где вызывается внешняя команда
- Понимать роль оболочки: кто именно режет строку на аргументы и разбирает метасимволы
- Объяснить, почему список аргументов без shell закрывает проблему

## Подтемы

- [ ] Инъекция с видимым выводом
- [ ] Слепая инъекция: задержки, запись в файл, внешние обращения
- [ ] Обход фильтров метасимволов

Точный список лаб бери на сайте PortSwigger — он меняется. Здесь подтемы, а не оглавление.

## Как чинится в коде

Не вызывать оболочку: передавать команду **списком аргументов** (`subprocess.run([...])`
без `shell=True`). Тогда ввод остаётся одним аргументом и не может стать новой командой.

Если оболочка нужна — белый список допустимых значений. Экранирование метасимволов
вручную почти всегда оказывается неполным.
