# Контроль доступа

Тема фазы A · по плану — [декабрь 2026](../plan/months/2026-12.md) · назад к [плану](../appsec-plan.md)

## Что это

Приложение знает, кто пользователь, но не проверяет, **можно ли ему** именно это.
Самый частый класс в реальных продуктах и самый плохо ловящийся инструментами:
сканер не знает бизнес-правил, а из одного файла нарушение не видно.

## Что уметь к концу темы

- Отличать вертикальный обход от горизонтального
- Находить IDOR в чужом API по одним только именам параметров
- Объяснить, почему это плохо ловится статическим анализом — вопрос с собеседования

## Подтемы

- [ ] Вертикальный обход: доступ к функциям администратора
- [ ] Горизонтальный обход и IDOR: чужие объекты по идентификатору
- [ ] Доступ по неугаданному URL как единственная защита
- [ ] Проверка на клиенте вместо сервера
- [ ] Обход через параметры, заголовки и методы

Точный список лаб бери на сайте PortSwigger — он меняется. Здесь подтемы, а не оглавление.

## Как чинится в коде

Проверка на каждом обращении к объекту, на сервере, **по умолчанию запрещено**.
Не «скрыть кнопку», а «не отдать данные».

Идентификаторы объектов не угадываются — но неугадываемость это не защита,
а затруднение. Централизованная проверка вместо копии условия в каждом обработчике:
одна забытая копия и есть типичная уязвимость.
