# Термины: Claude Code

Самопроверка по месяцу работы. Пройдено 2026-09-11.

## 1. `git rm -r --cached .venv`

**В:** Что делает?
**О:** Убирает из репозитория, но оставляет на диске.
> `--cached` означает «только из индекса». Окружение остаётся живым — поэтому команда безопасна.

## 2. Субагент

**В:** Зачем выносить ревью в субагента, а не делать в основной сессии?
**О:** У него свой контекст — чтение большого диффа не забивает окно основной сессии.
> Плюс специализация: `security-reviewer` ищет конкретные классы уязвимостей, общий ревьюер разбавляет внимание между стилем, логикой и безопасностью.

## 3. Хук против CLAUDE.md

**В:** В чём принципиальная разница?
**О:** Хук — механизм, срабатывает всегда. CLAUDE.md — договорённость, соблюдается почти всегда.
> Отсюда решение по `[skip-guard]`: проверку ветки повесили на хук, а запрет агенту применять обход — в CLAUDE.md, потому что механизмом его не выразить.

## 4. `git commit --amend`

**В:** Что делает и когда нельзя применять?
**О:** Заменяет последний коммит новым. Нельзя после того, как ветка запушена.
> Переписывание истории безопасно только до публикации — после она ломает работу тем, кто уже забрал ветку.

## 5. `message.content`

**В:** Почему текст ответа приходится собирать, а не брать одним полем?
**О:** Ответ состоит из блоков — текст, вызовы инструментов и прочее; текстовых блоков может быть несколько.
> Ответ это структура, а не строка. Отсюда накопление в переменную вместо печати в цикле.

## 6. system_prompt против prompt

**В:** В чём разница?
**О:** `system_prompt` — правила и формат, `prompt` — данные для обработки.
> Проверено делом: пока в `prompt` уходил текст про `sys.argv` вместо содержимого файла, модель принимала его за задание себе.

## 7. `sys.stderr`

**В:** Зачем печатать ошибки туда, а не обычным `print`?
**О:** Чтобы при перенаправлении вывода в файл туда попал только результат, а жалоба осталась на экране.
> Два потока существуют ровно для этого: данные и диагностика не смешиваются.

## 8. MCP

**В:** Что это?
**О:** Протокол, по которому агент получает доступ к внешним инструментам и данным.
> Через него подключён GitHub — работа с PR и issues напрямую, без ручного копирования.

## 9. Область действия хуков плагина

**В:** Почему хук не помешал закоммитить в master руками из терминала?
**О:** Хуки плагина реагируют на действия агента, а не на команды в терминале.
> Полное покрытие даёт обычный git-хук в `.git/hooks/`, но он живёт в одном репозитории и вместе с плагином не переезжает. Осознанный компромисс.
